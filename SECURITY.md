# Security policy

Please do not open a public issue for exposed credentials, tokens, private research data or other potentially sensitive material.

If GitHub private vulnerability reporting is enabled for this repository, use its private reporting interface. If it is not available, use a private channel established by the repository owner. Do not include sensitive details in public discussions, pull requests or commits.

## Scope

Security reports may cover dependency risks, GitHub Actions workflows, ways to bypass the public-build scanner, exposure of private or unpublished data, and integrity of the static site or downloadable database. A factual correction to public policy metadata, provenance or analysis should normally follow the review process in [CONTRIBUTING.md](CONTRIBUTING.md), unless the correction itself would expose sensitive material.

Reports are assessed according to the information available and the project’s research scope. This policy does not make promises about response times, remediation outcomes or service availability.
