# Data dictionary

Canonical records are UTF-8 JSON objects, one record per file. Every record has an `id` (lowercase hyphenated string), `entity_type`, `publication_status` (`draft`, `pending_review`, `verified`, or `published`), and UTC ISO-8601 `created_at` and `updated_at` timestamps. All are required. Public repository visibility does not make a draft part of the reviewed corpus: only `published` records are exported to `public-data.json`.

| Entity | Field (type; required) | Provenance and allowed values |
| --- | --- | --- |
| Policy | `name`, `short_name`, `summary`, `policy_family`, `scope_note` (string; yes); `policy_status` (string; yes) | Analytical research description. `policy_status`: `active`, `completed`, `withdrawn`, `superseded`. |
| Document | `slug`, `official_title`, `short_title` (string; yes); `publication_date` (ISO date; yes); `language` (string; yes); `celex`, `eli`, `official_summary` (string or null; no identifier where unassigned) | Title, date, language, identifiers and summary are official metadata. `language` is `en`. |
| Document | `document_type`, `legal_status` (string; yes) | Classification from official form/legal state. `document_type`: `communication`, `coordinated_plan`, `expert_guidelines`, `white_paper`, `legislative_proposal`, `regulation`. `legal_status`: `non_binding`, `proposed`, `adopted`, `in_force`, `withdrawn`, `superseded`. |
| Document | `institution_roles` (array of `{institution_id, role}`; yes); `policy_ids`, `concept_ids`, `source_ids` (unique ID arrays; yes) | Institution identity and role are official; policy/concept links are analytical. Roles: `author`, `proposer`, `adopter`, `publisher`, `contributor`. |
| Document | `corpus_assessment` (object; yes) | Analytical, explicitly separate from official metadata: `corpus_tier` (`core`, `directly_related`, `contextual`, `excluded`), `policy_stage` (`agenda_setting`, `coordination`, `consultation`, `proposal`, `negotiation`, `adoption`, `implementation`), `inclusion_rationale`, `researcher_notes`, `review_status` (`unverified`, `pending`, `verified`), `reviewed_by`, `reviewed_at`. |
| Document | `snapshots` (array; optional) | Provenance records only for an actually retrieved official file: `{id, source_id, retrieved_at, format, content_hash, archived_path}`. `archived_path` is nullable. |
| Event | `event_type`, `event_date`, `title`, `description`, `policy_id`, `document_id` (nullable), `source_id` (all required) | Date/title/source are official evidence; description may be concise editorial context. `event_type`: `proposal`, `publication`, `adoption`, `entry_into_force`, `application`, `amendment`, `withdrawal`, `implementation`. |
| Concept | `name`, `definition`, `research_scope`, `notes` (string; yes); `eurovoc_uri` (URI or null; yes) | Analytical research vocabulary unless a EuroVoc URI is supplied. |
| Institution | `official_name`, `short_name`, `institution_type`, `official_url` (string/URI; yes) | Official organisational metadata. |
| Relationship | `source_entity_type`, `source_entity_id`, `target_entity_type`, `target_entity_id`, `relationship_type`, `basis`, `rationale` (nullable), `evidence_source_id` (nullable), `verification_status` (all required) | Endpoints are typed IDs. Types: `policy`, `document`, `event`, `concept`, `institution`, `relationship`, `source`; relationships: `part_of`, `precedes`, `adopted_as`, `replaces`, `amends`, `implements`, `based_on`, `related_to`, `supersedes`; basis: `official` or `analytical`; verification: `unverified`, `pending`, `verified`. Analytical links require a rationale and evidence source. |
| Source | `source_type`, `url`, `publisher`, `retrieved_at`, `last_verified_at`, `verification_note` (all required) | Official provenance. `source_type`: `eur_lex`, `eli`, `commission_webpage`, `official_pdf`, `publications_office`. |

References are validated before SQLite generation. Published records may refer only to published records; published documents, events and relationships require a recorded source. The generated SQLite database normalises the document junctions, corpus assessments and snapshots; it is a build artefact, not an editing surface.
